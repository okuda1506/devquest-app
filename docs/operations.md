# DevQuest 運用手順

## 公開前の確認

1. [README の初回公開設定](../README.md#初回の公開設定)に従い、公開先・OAuth の許可 URL・Supabase の接続先をそろえる
2. テスト環境で `npm run lint`、`npm test`、`bash scripts/test-db.sh`、`npm run build` を実行する
3. 初回利用者として GitHub でログインする。キャンセル後にやり直し、初出勤の途中でブラウザを閉じて再開する。公開範囲または URL の異なるリポジトリで登録を試し、正しい THREAD リポジトリを登録する
4. DEV-101 で未提出 → push → 実行中 → 不合格 → 修正して再 push → 合格 → PR マージ → DEV-102 解放を確認する。不合格と合格は Actions のリンク先で同じコミットか確認する
5. 実行中の再 push、Actions の中断、連続した結果確認を試す。古いコミットで合格にならず、通知が重複しないことを確認する
6. DEV-124 完了から DEV-105 を解放する。旧版で DEV-104 まで完了した学習者のデータをテスト環境で用意し、DB 更新後に DEV-113 が一度だけ配布されることを確認する

## 死活監視と問い合わせ

```bash
node scripts/check-service.mjs 'https://okuda1506.github.io/devquest-app/' \
    'https://PROJECT_REF.supabase.co/functions/v1/quest'
```

監視サービスから公開 URL と `/functions/v1/quest/health` を定期確認する。後者は Edge Function から課題順テーブルへの読み取りを確認し、異常時は HTTP 503 を返す。OAuth と GitHub API の動作は、個別の通し確認とログで確認する。通知先は運用担当者が設定する。

- HTTP 429 が増えたら GitHub API の利用上限を確認する。確認ボタンの連打を避け、回復後に同じ課題から再確認する
- HTTP 5xx が続いたら Supabase の Logs で Edge Function と DB の状態を確認する。停止中なら再開し、死活確認と直近の採点の再確認を行う
- エラー率の初期目安は直近15分の採点が10件以上あり、うち5xxが5%以上の場合。件数が少ない間は5xxの連続発生から通知する。学習者の入力に由来する4xxを5xxの集計に含めない
- 問い合わせでは課題ID・発生時刻・GitHub Actions の URL を受け取る。Supabase の `quest_request` ログを時刻・`taskId`・`runId` で検索し、`learnerId`・`repoId`・`sha`・`outcome`・HTTP ステータスを照合する。ログのアクセス権は運用担当者に限る
- ログには OAuth コードやトークン、リクエスト本文を含めない。調査では採点 API から再確認し、進捗を直接書き換えない

## 採点基準の更新と切り戻し

フロントエンドのコミット、適用済み DB マイグレーション、Edge Function のコミット、THREAD の採点タグと SHA をリリース記録に残す。採点基準を変える場合は THREAD のタグを先に公開し、DB と Edge Function を反映してからフロントエンドを公開する。新規・進行中の両方のデータで課題の解放を確認する。

表示だけに不具合がある場合は、直前のフロントエンドと現在の API の互換性を確認してからフロントエンドを戻す。採点基準の不具合は、学習者が使っているタグと進捗を確認し、対応する Edge Function との組み合わせをテスト環境で検証する。適用済みマイグレーションの履歴は書き換えず、DB 修正は追加マイグレーションとして検証する。

## バックアップの復元

`bash scripts/test-db.sh` は使い捨ての PostgreSQL で学習者データを作り、バックアップを別の DB へ復元して内容が一致することを確認する。本番では Supabase の契約に合うバックアップを選び、Auth とアプリのテーブルを含む復元を隔離した環境で試す。取得日時、復旧範囲、復元所要時間を記録する。

復元後はログイン、登録リポジトリ ID、完了コミット、通知件数、次の課題解放を確認する。本番を復元する必要がある場合は、復元点以降の学習データへの影響を確認してから実行する。バックアップの保存期間と問い合わせ対応時の開示範囲は運用担当者が決める。
